Cursor Tips & Tricks

A rapid-fire showcase of power-user features and hidden gems in Cursor. Each tip is 2–3 minutes — quick demo, key takeaway, move on. These are the shortcuts and workflows that separate beginners from power users.

1. Multi-Cursor + AI

"Most of you know multi-cursor editing — hold Alt and click to place multiple cursors. But did you know you can select multiple similar code blocks and then hit Cmd+K to apply an AI transformation to all of them at once? This is incredibly powerful for batch refactoring."

The Workflow

  1. Cmd+D — Select the next occurrence of the current word. Repeat to select more.
  2. Cmd+Shift+L — Select all occurrences at once.
  3. Cmd+K with multiple selections — AI applies the same transformation to each selection independently.

When to Use It

  • Converting multiple var declarations to const/let with AI-chosen types
  • Adding JSDoc comments to several function signatures at once
  • Renaming patterns across a file where find-and-replace isn't smart enough

Key Takeaway

Multi-cursor + Cmd+K = batch AI edits. Faster than editing one by one, smarter than regex find-and-replace.

2. AI Commit Messages

"Stop spending time writing commit messages. Cursor can read your staged diff and generate a meaningful, conventional commit message for you. It looks at the actual changes — not just file names — so the messages are surprisingly good."

How It Works

  1. Stage your changes with git add.
  2. Open the Source Control panel (Ctrl+Shift+G).
  3. Click the sparkle icon next to the commit message input.
  4. Cursor reads the diff, generates a message, and pre-fills the input.

Key Takeaway

One click to generate a commit message from your diff. Edit if needed, then commit. Saves 30 seconds every time.

3. Notepads

"Notepads are like persistent scratch pads that live across conversations. Think of them as reusable context blocks. You can store architecture decisions, API response examples, or complex requirements, and then reference them from any Chat or Composer session with the @ symbol."

Creating & Using Notepads

  • Open the Notepads panel in the sidebar (or Cmd+Shift+P → "Notepad").
  • Create a new notepad with a descriptive name (e.g., "API Contract", "Migration Notes").
  • Write or paste your content — free-form text, code snippets, whatever.
  • In Chat or Composer, type @notepad-name to inject that notepad's content as context.

Good Use Cases

  • API response shapes — paste a sample JSON response so the AI always knows the structure.
  • Architecture decisions — "We use constructor injection, not field injection."
  • Complex prompts — store a well-tuned prompt you reuse across sessions.

Key Takeaway

Notepads = persistent context you can reference with @. No more re-explaining the same thing every conversation.

4. .cursorignore & .cursorindexingignore

"You control what the AI sees. These two files let you draw boundaries — one prevents indexing, the other prevents all access. This matters for security, performance, and keeping the AI focused on the right code."

The Two Files

.cursorindexingignore

  • Files are not indexed (no embeddings, no semantic search).
  • AI can still see them if you explicitly open or @-reference them.
  • Good for: node_modules/, dist/, generated code, large data files.

.cursorignore

  • Files are completely invisible to the AI — never indexed, never readable.
  • Good for: .env, secrets, credentials, proprietary code you never want sent.

Example

# .cursorignore
.env
.env.*
secrets/
credentials.json

# .cursorindexingignore
node_modules/
dist/
build/
*.min.js

Security Note

If your project has secrets or proprietary code, set up .cursorignore on day one. This is your first line of defense against accidental data leakage.

5. Saving Prompts as Commands

"If you find yourself typing the same prompt over and over — 'review this for security issues', 'add error handling', 'write tests for this' — stop and turn it into a slash command. It takes 30 seconds and saves you minutes every day."

Quick Recipe

  1. Create .cursor/commands/your-command.md
  2. Write your prompt as markdown — the file name becomes the command name.
  3. In Chat, type /your-command and it expands into the full prompt.

Example: A Quick Review Command

# .cursor/commands/security-review.md

Review the selected code for security vulnerabilities:

- SQL injection
- XSS (cross-site scripting)
- Authentication/authorization gaps
- Secrets or credentials in code
- Input validation issues

Report findings as a numbered list with severity (HIGH/MEDIUM/LOW).

Key Takeaway

Good prompts are reusable. Turn them into commands and share them with your team via version control.

6. Navigating Large Files

"Large files are where Cursor really shines over a plain text editor. Instead of scrolling through 500 lines looking for a method, you can ask the AI or use the built-in symbol navigation to jump right to it."

Navigation Shortcuts

  • Cmd+Shift+O — Go to Symbol in the current file. Type a method name and jump straight to it.
  • Cmd+T — Go to Symbol across the entire workspace. Find any class, function, or variable.
  • Breadcrumbs (top of editor) — Click to navigate the file structure. Shows class → method hierarchy.
  • Outline View (sidebar) — Tree view of all symbols in the file. Click to jump.

AI-Assisted Navigation

  • In Chat: "Where is the checkout logic in this file?" — AI tells you the exact line.
  • @file + question — AI reads the entire file and answers about structure.
  • Cmd+Click on any symbol — Go to Definition. Works across files and even into dependencies.

Key Takeaway

Cmd+Shift+O for within-file, Cmd+T for workspace-wide. Combine with AI for "find the logic that does X."

7. Settings Sync

"If you use Cursor on multiple machines — work laptop, personal machine, maybe a VM — settings sync keeps everything consistent. Your keybindings, extensions, themes, and Cursor-specific settings follow you everywhere."

What Syncs

  • Settings — editor preferences, AI model selection, privacy settings.
  • Keybindings — custom shortcuts.
  • Extensions — installed extensions and their settings.
  • Themes — color theme and icon theme.

What Doesn't Sync (by design)

  • Project-level config — .cursor/ folder, rules, commands, skills. These live in the repo and are shared via git.
  • MCP server configs — These often contain machine-specific paths or tokens.

Key Takeaway

Personal prefs sync via your account. Team conventions sync via the .cursor/ folder in git. Both are important.

8. Token Budget Tricks

"Every AI request has a token limit. The more context you send, the less room the model has to think and respond. Keeping your context lean isn't just about cost — it actually produces better results. Here are the tricks."

Lean Context Strategies

  • Be specific with @-references — Use @file for a single file, not @codebase when you know where the code is.
  • Use @symbol — Reference a specific function or class instead of the whole file.
  • Trim conversation history — Start a new Chat session when switching topics. Long conversations accumulate stale context.
  • Use .cursorindexingignore — Keep noise out of @codebase results.
  • Small, focused prompts — "Add null check to getProduct()" beats "make the product service more robust."

Signs Your Context Is Too Large

  • The AI "forgets" instructions you gave earlier in the conversation.
  • Responses become generic or miss specifics about your code.
  • You see truncation warnings or slower response times.

Key Takeaway

Less context = better results. Be surgical with @-references. Start fresh conversations often.

9. Quick Fixes from Errors

"When you see a red squiggly in your code, don't just read the error — click on it. Cursor adds AI-powered fix suggestions right alongside the standard language server fixes. Often it can resolve the error in one click."

The Workflow

  1. Hover over a red/yellow underline, or click the lightbulb icon.
  2. Look for "Fix with AI" in the quick actions menu.
  3. Cursor reads the error, the surrounding code, and proposes a fix inline.
  4. Accept, modify, or reject the suggestion.

Works Great For

  • Missing imports — AI adds the right import statement.
  • Type mismatches — AI converts or casts to the correct type.
  • Missing method implementations — AI generates the method stub.
  • Syntax errors — AI corrects the syntax in context.

Pro Tip: Fix from Terminal

When a build or test fails in the terminal, click the error message. Cursor can read the stack trace and offer to fix the source file directly. Use @terminal in Chat to pass the terminal output as context.

Key Takeaway

Errors are fix opportunities. Click the lightbulb, let AI resolve it. Works from both the editor and the terminal.

10. Combining Primitives

"This is the meta-tip. Everything we have seen today — Rules, Commands, Skills, Hooks, Subagents — these are individual primitives. The real power comes from chaining them together into automated workflows. Let me show you what that looks like."

Example: The “Add Feature” Pipeline

Imagine you want to add a new REST endpoint. Here is how the primitives chain together:

  1. Skill (/add-feature) — Orchestrates the multi-step process: create model, repository, service, controller, tests.
  2. Rules (.cursor/rules/) — Automatically enforce coding standards as each file is generated (constructor injection, ResponseEntity returns, etc.).
  3. Hook (afterFileEdit) — Auto-formats every Java file immediately after the agent writes it.
  4. Subagent (verify-agent) — Runs in the background to compile and test after each step.
  5. Command (/review) — Final review pass on the generated code.

The Primitives Cheat Sheet

Rules

Always-on guardrails. The AI reads them automatically.

Prevention layer

Commands

On-demand prompt shortcuts. You invoke them with /name.

Reuse layer

Skills

Multi-step workflows with templates and supporting files.

Orchestration layer

Hooks

Scripts that run before/after agent actions.

Enforcement layer

Key Takeaway

Individual primitives are useful. Combined primitives are transformative. Think in pipelines, not individual tools.
